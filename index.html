-- Pola yang dipakai PERSIS SAMA seperti nomor_wo (Work Order, "WO-0001")
-- & nomor_jc (Job Card, "JC-0001") yang sudah lebih dulu ada di aplikasi:
--   1) tambah kolom teks nomor_xxx (nullable, tidak mengubah data lama)
--   2) buat sequence nomor urut per tabel
--   3) trigger BEFORE INSERT: isi otomatis nomor_xxx saat baris baru dibuat
--   4) backfill: baris LAMA yang nomor_xxx-nya masih kosong diberi nomor
--      urut sesuai urutan created_at (paling lama = nomor terkecil)
--
-- Setelah menjalankan SQL ini, tidak perlu ubah kode aplikasi lagi --
-- aplikasi (identifikasi-kendaraan.html versi terbaru) sudah menampilkan
-- kolom nomor ini di setiap daftar/tabel terkait.
-- =========================================================================

-- ---- kendaraan -> VH-0001 ... ------------------------------------------
alter table kendaraan add column if not exists nomor_kendaraan text;

create sequence if not exists kendaraan_nomor_seq start 1;

create or replace function set_kendaraan_nomor()
returns trigger as $$
begin
  if new.nomor_kendaraan is null then
    new.nomor_kendaraan := 'VH-' || lpad(nextval('kendaraan_nomor_seq')::text, 4, '0');
  end if;
  return new;
end;
$$ language plpgsql;

create or replace trigger trg_kendaraan_nomor
before insert on kendaraan
for each row execute function set_kendaraan_nomor();

update kendaraan t
set nomor_kendaraan = 'VH-' || lpad(nextval('kendaraan_nomor_seq')::text, 4, '0')
from (
  select id, row_number() over (order by created_at asc nulls last) as rn
  from kendaraan
  where nomor_kendaraan is null
) x
where t.id = x.id and t.nomor_kendaraan is null;

function extractJson(text: string) {
  const fenced = text.match(/```(?:json)?\s*([\s\S]*?)```/i);
  const raw = fenced ? fenced[1] : text;
  const start = raw.indexOf('{');
  const end = raw.lastIndexOf('}');
  if (start === -1 || end === -1 || end < start) throw new Error('JSON tidak ditemukan pada balasan AI');
  return JSON.parse(raw.slice(start, end + 1));
}

    }, 500);

  } catch {

        'content-type': 'application/json',
        'x-api-key': apiKey,
        'anthropic-version': '2023-06-01'
      },
      body: JSON.stringify({
        model,
        max_tokens: 2000,
        tools: [{ type: 'web_search_20250305', name: 'web_search', max_uses: 5 }],
        messages: [{ role: 'user', content: prompt }]
      })
    });

    if (!resp.ok) {
      const errText = await resp.text();
      return jsonResponse({ ok: false, error: 'AI_API_ERROR', message: errText.slice(0, 500) }, 502);
    }

    const data = await resp.json();
    const content: any[] = data.content || [];
    const textBlocks = content.filter((b) => b.type === 'text').map((b) => b.text);
    const sourcesFromCitations: { title: string; url: string }[] = [];
    for (const b of content) {
      if (b.type === 'text' && Array.isArray(b.citations)) {
        for (const c of b.citations) {
          if (c.url) sourcesFromCitations.push({ title: c.title || c.url, url: c.url });
        }
      }

    }

      parsed.sources = sourcesFromCitations.slice(0, 6);
    }

    return jsonResponse({ ok: true, mode, result: parsed });
  } catch (e) {
    return jsonResponse({ ok: false, error: 'FUNCTION_ERROR', message: String(e) }, 500);

Support / Application Concept

Application Concept: Auto Maintenance Repair Management

Ringkasan strategi dan arah pengembangan AutoPrima. Dokumen lengkap & dapat diedit ada di Claude Docs terpisah.

Summary & Purpose

AutoPrima adalah sistem manajemen perawatan kendaraan pribadi (mobil/motor) yang mengadopsi pendekatan reliability-centered maintenance (RCM) yang lazim dipakai untuk merawat mesin/alat kompleks — bukan sekadar pencatatan servis bengkel, melainkan program perawatan terstruktur untuk menjaga kendaraan tetap andal, aman, dan layak jalan.

Setiap kendaraan diberi identitas lengkap (kategori, model, type, jenis, merk) dan riwayat tercatat rapi per komponen, sehingga keputusan servis didasarkan pada data (KM, usia part, siklus pemakaian), bukan perkiraan.

Assumptions Used
  • Pengguna: individu pemilik kendaraan pribadi, bisa mengelola beberapa kendaraan dari satu akun.
  • Cakupan kendaraan: mobil dan motor pribadi, dikelompokkan berdasarkan kategori, model, type, jenis, dan merk.
  • Kepatuhan regulasi: mengacu ke UU LLAJ dan Peraturan Polri untuk kelaikan jalan; kerangka ISO 9001/14001 dan metodologi reliability-centered maintenance (RCM) diadopsi sebagai metodologi, bukan kewajiban sertifikasi.
  • Konektivitas & data: multi-device, terhubung ke database gratis (Supabase).

Service Standards & Quality Management (Module 4)

AutoPrima mengadopsi kerangka ISO 9001 (manajemen mutu) & ISO 14001 (manajemen lingkungan) sebagai metodologi kerja — bukan sebagai sertifikasi yang wajib dimiliki pemilik kendaraan pribadi. Prinsip-prinsipnya menjelaskan mengapa aplikasi disusun dengan program perawatan terjadwal, log riwayat, dan tracking part, bukan sekadar catatan bebas.

ISO 9001:2015 PrincipleImplementation in AutoPrima
Fokus PelangganKendaraan & kenyamanan pemilik jadi pusat — riwayat lengkap per kendaraan, bukan per bengkel.
KepemimpinanPemilik kendaraan berperan sebagai penentu kebijakan perawatan (approve Work Order, tetapkan prioritas).
Keterlibatan PersonelJob Card mencatat teknisi yang mengerjakan tiap rincian tugas, bukan hanya status Work Order.
Pendekatan ProsesAlur Program → Work Order → Job Card → Riwayat berjalan sebagai proses terhubung, bukan modul terpisah.
Peningkatan BerkelanjutanToolkit analisis (PDCA, FMEA, PICA) dipakai saat kerusakan berulang terjadi.
Pengambilan Keputusan Berbasis BuktiRekomendasi aksi mengacu ke data KM/usia/cycle aktual, bukan perkiraan.
Manajemen RelasiData bengkel/mekanik & pemasok part (modul Parts, Workshop/Resource) dikelola sebagai mitra jangka panjang.

Siklus PDCA (Plan – Do – Check – Act) dipetakan ke modul AutoPrima: Plan = Maintenance Program & Plan, Do = Work Order & Job Card, Check = Riwayat & Control/Monitoring, Act = Toolkit Analisis & Rekomendasi Aksi.

ISO 14001:2015 Principle (workshop-relevant)Implementation in AutoPrima

Ringkasan ini memakai konsep umum ISO 9001:2015 & ISO 14001:2015 yang sudah dipublikasikan luas (prinsip & siklus PDCA), bukan kutipan teks resmi standar — teks lengkap ISO berbayar & berhak cipta. Untuk interval servis baku, AutoPrima mengacu ke manual resmi pabrikan/buku servis Jepang per model (lihat template di modul Program) — selalu sesuaikan dengan buku manual resmi kendaraan Anda.

Manufacturer Standards & Tiered Reliability Program (Module 22)

Selain ISO 9001/14001, desain program perawatan AutoPrima juga terinspirasi dari dua hal: praktik perawatan pabrikan/merek Jepang (mis. Honda, Suzuki, Toyota), dan konsep umum manajemen keandalan berjenjang yang dipakai luas untuk merawat mesin/alat kompleks. Yang diambil hanya pola pikirnya — bukan rujukan ke regulasi, otoritas, atau sertifikasi industri tertentu di luar konteks kendaraan bermotor jalan raya.

Japanese Practice ConceptImplementation in AutoPrima
Official service manual per modelInterval KM/waktu di modul Program & Plan mengikuti buku manual resmi tiap merek/model, bukan angka generik pukul rata.
Kaizen (continuous incremental improvement)Toolkit Analisis (PDCA) dipakai tiap kali ditemukan pola kerusakan berulang, bukan diperbaiki sekali lalu dilupakan.
Genba (direct observation of actual conditions)Kondisi aktual dicatat di Job Card & Riwayat, bukan asumsi dari jadwal semata.
Self-maintenance by the ownerPengecekan harian sederhana (tekanan ban, oli, lampu) jadi kebiasaan pemilik, bukan hanya tugas teknisi bengkel.
Tiered Service LevelCoverageExample Trigger
Tier 1 – Routine InspectionBasic visual & functional check (oil, tires, lights, brakes)Every use / weekly
Tier 2 – Minor Periodic ServiceScheduled consumables replacement (oil, filters, spark plugs)Short KM/time interval
Tier 3 – Major Periodic ServiceInspection & service of major systems (brakes, suspension, transmission, electrical)Medium–long KM/time interval
Tier 4 – Full Overhaul/ReconditioningFull teardown & inspection of major componentsVery high age/KM or signs of declining reliability

Idealnya, tugas & interval tiap tingkat ditentukan dari analisis konsekuensi kegagalan tiap komponen — bukan sekadar jadwal tetap yang dipukul rata — prinsip inilah yang mendasari Reliability Control Program & Toolkit Analisis (FMEA) di AutoPrima: makin kritikal dampak kegagalan suatu part, makin ketat pemantauannya.

Tingkatan di atas adalah adaptasi pola pikir manajemen keandalan mesin kompleks untuk konteks kendaraan pribadi, bukan rujukan ke sertifikasi, regulasi, atau otoritas industri tertentu — AutoPrima tidak mengklaim kepatuhan terhadap standar industri apa pun di luar konteks kendaraan bermotor jalan raya.

Modules & Key Features
  1. Vehicle Identification — profil lengkap per kendaraan (modul yang aktif di tab Home).
  2. 5-Year Maintenance Program — peta jangka panjang perawatan besar & penggantian part utama.
  3. 1-Year Maintenance Plan — turunan tahunan dari program 5 tahun.
  4. Maintenance Activity Schedule — mingguan/bulanan/3-bulanan/5-bulanan, dipicu KM/usia/cycle.
  5. Reliability Control Program — pelacakan keandalan tiap part/komponen.
  6. Maintenance History & Log, Control & Monitoring, Cost Management, Spare Part Information.
  7. Analysis Toolkit (PDCA, FMEA, PICA, 5W1H, fishbone) & Action Recommendations preventive/predictive.
